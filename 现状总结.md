## 二、当前状态

### ✅ 已完成的模块

| 模块 | 覆盖端 | 验证 |
|------|--------|------|
| mDNS register + browse | Desktop / Android | ✅ 双方各自注册成功 |
| Unicast fallback TCP probe | Desktop (Rust core) | ✅ 子网扫 7 端口，32 线程 |
| Desktop ApiServer (28792) | Desktop | ✅ curl / ureq 均可用 |
| Desktop sync-with-device (HTTP) | Desktop | ✅ 端到端测试通过 |
| UniFFI scaffold + C-ABI | Rust core | ✅ 已生成 Kotlin 绑定 |
| Android Discovery 委托 UniFFI | Android | ✅ `DiscoveryService.android.kt` 基于 Rust |
| PC ↔ Phone curl 双向 | HTTP 层 | ✅ PC curl 28792 / Phone curl 28792 双向可达 |
| PC unicast 探测到 Phone 18792 | TCP 层 | ✅ `connect OK 192.168.5.130:18792` |

### ⚠️ 已知问题

| 问题 | 根因 | 影响 |
|------|------|------|
| **mDNS 双向不通** | Windows 多网卡: Mihomo / Radmin VPN 劫持多播, 12 条 metric=256 的路由竞争 | Desktop ↔ Android 无法通过 mDNS 发现 |
| **Android 无 HTTP server** | `ApiServer` 的 `start_with_callbacks` 已 UniFFI 导出但无人调用 | Android 端 18792 端口空着，PC 探测到后 verify 失败 |
| **Android 无 sync** | `sync_with_device` 未暴露 UniFFI; Android 端无真实 AppState | 无法触发跨设备同步 |
| **Android 历史数据为 mock** | `mockClipboardItems` 假数据 | 即使 sync 成功也无有意义数据可交换 |
| **iOS 端完全空白** | 用户要求暂不处理 | — |

### 🔄 正在做的工作

- `sync_device.rs` 添加 `#[uniffi::export]` 到 `sync_with_peer` 函数（纯 HTTP 版本，不依赖 `Arc<AppState>`）
- 将 `SyncReport` 中的 `usize` 改为 `u64`（UniFFI 不支持 `usize`）

## 三、同步闭环 (单次 sync_with_device 调用)

```
本地 (B)                                              对端 (A)
───────                                               ────────
0. 抓 latest_local_text  ◄─ pull 之前先抓,
    否则 pull 后"最新"变成对端条目

1. GET /clipboard/history
   ◄────────────────────────────────────────────────── JSON
2. 遍历, hash 去重, 文本类型 → push_clipboard
   (写到本地 DB + 内存)

3. POST /clipboard/copy
   body = latest_local_text  ──────────────────────►
                                            on_remote_copy()
                                            → state.push_clipboard
                                            → A DB 写入 from-B
```
